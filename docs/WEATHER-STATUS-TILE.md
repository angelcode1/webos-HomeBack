# Status weather tile

HomeBack renders a passive status tile at the fixed right edge of the ribbon. The tile is intentionally outside launcher-card navigation, ordering, editing and focus state.

## Weather data flow

The app renders the TV's local clock directly and asks the HomeBack helper service for a normalized weather snapshot. The helper caches successful weather for 20 minutes and may display a stale snapshot for up to two hours if refreshes fail.

Stock-weather **capability discovery** is deliberately separate from the user's **Weather Location Setting**.

After HomeBack bootstrap, the helper reads `modelName`, `firmwareVersion` and `sdkVersion` from `com.webos.service.tv.systemproperty/getSystemInfo`. A persisted stock-weather verdict is reusable only when those three values **and the HomeBack version** match the current process. A TV firmware/webOS upgrade therefore invalidates the old verdict even if HomeBack itself was not upgraded.

If no matching capability record exists, HomeBack probes the known local LG preference sources for stock weather. A positive result is definitive and is persisted. A negative result is persisted only when the probe is also definitive: calls completed successfully without exposing weather, or the relevant method is definitively absent or denied. Timeouts, startup races, unavailable/unready services and other inconclusive failures are **not** written to disk, so the next service launch probes again.

If platform identity itself cannot be read, HomeBack does not trust or write persistent capability state for that run. It may still probe and use stock weather in memory for the current service process.

The machine-written capability record is stored at:

```text
/var/lib/homeback/weather-capability.json
```

The former `/home/root/.config/homeback/weather-capability.json` location is treated as legacy machine state and is removed when the new store is first read.

## Weather Location is dynamic

LG's Weather Location Setting is **not** stored in the capability record. HomeBack reads it again on each actual weather refresh. Because the successful weather snapshot itself is cached for 20 minutes, ordinary ribbon opens do not repeatedly hit the preference service.

If stock weather is available, HomeBack queries only the selected stock-weather source for temperature/condition and independently reads the current Weather Location for the label. If stock weather is unavailable, HomeBack uses the current LG Weather Location when available; otherwise it asks `com.webos.service.location/getLocationUpdates` for coordinates and then requests current conditions from Open-Meteo.

That final path is the intended fallback for older webOS TVs that expose no usable stock-weather values.

## Reset capability discovery

To force stock-weather capability discovery again without changing TV firmware or HomeBack version, remove the machine-state file and restart the helper service:

```sh
rm -f /var/lib/homeback/weather-capability.json
luna-send -n 1 -f \
  luna://com.homebrew.homeback.service/restartService \
  '{}'
```

The next HomeBack launch/weather request performs a fresh capability probe. Do not edit this file as user configuration.

## Conditions

Weather responses are normalized to these UI conditions: clear, partly cloudy, cloudy, rain, heavy rain, storm, snow, fog, and unknown. The status tile uses bundled monochrome SVG glyphs and does not depend on external icon assets.

## Failure behavior

Weather is optional. Missing LG weather services, denied location access, failed geocoding or network failures do not affect launcher navigation or visibility. The tile continues to show the clock and displays `--°` until a weather snapshot is available.
